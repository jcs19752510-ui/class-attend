# 법무 검토 체크리스트 — class-attend

> 이 문서를 `privacy_policy_draft.md`, `consent_texts_draft.md`와 함께
> 변호사/법무법인에 전달하세요. 일반적인 서비스라면 필요 없을 수도 있는
> 항목까지 포함해, 이 프로젝트의 특수성(미성년자 + 프랜차이즈 다지점
> 구조)에서 특히 확인이 필요한 질문 위주로 정리했습니다.

## 1. 프랜차이즈 본사-지점 구조와 개인정보 책임 소재
- [ ] 본사(프랜차이즈 관리자)와 각 지점(원장)은 법상 하나의 "개인정보
      처리자"인가, 아니면 본사가 지점에 처리를 위탁하는 관계(수탁자)인가?
      (`ADR-001`: 기술적으로는 단일 DB에 `branch_id`로 지점을 구분하며,
      본사가 전체 지점 데이터를 조회할 수 있음 — 이 구조가 법상 어떻게
      해석되는지 확인 필요)
- [ ] 지점이 실제로는 별도 사업자(가맹점)인 경우, 본사-가맹점 간
      개인정보 처리위탁계약이 별도로 필요한가?

## 2. 미성년자(학생) 개인정보 처리
- [ ] 학생 등록 시 "원장이 보호자 동의를 확인했다고 체크"하는 현재
      방식이, 만 14세 미만 아동의 법정대리인 동의 요건(개인정보보호법
      제22조의2)을 충족하는가? 아니면 보호자로부터 직접 서면/전자 동의를
      받아 증빙을 보관해야 하는가?
- [ ] 만 14세 이상 미성년자(중·고등학생)의 경우 본인 동의만으로
      충분한가, 별도 취급이 필요한가?
- [ ] 학생 개인정보 최소 수집 원칙 관점에서, 현재 수집 항목(이름·생년월일·
      학생연락처·보호자연락처)이 "목적 달성에 필요한 최소한"에 해당하는가?

## 3. 보유기간·파기
- [ ] 퇴원 후 365일 보유 → 마스킹(행 삭제 아님) 방식(ADR-005)이 법상
      "파기"로 인정되는가, 아니면 익명화/가명처리 수준의 추가 조치가
      필요한가?
- [ ] 감사로그(AuditLog)를 영구 보관하는 것이 개인정보 보유기간 원칙과
      충돌하지 않는가? (감사로그에는 파기 전 PII 값을 남기지 않도록
      이미 구현되어 있음 — `att_u6_trd.md` §0-1 참고)
- [ ] 학부모(회원) 계정의 탈퇴·파기 정책이 아직 미정 — 필요한 최소
      정책은 무엇인가?

## 4. 위탁 및 제3자 제공
- [ ] 이메일 발송(임시 비밀번호 등)을 외부 서비스(예: Resend)에 맡길
      경우, 위탁계약 체결과 개인정보처리방침 내 위탁사 명시가 필요한가?
- [ ] 클라우드 인프라(Vercel, 관리형 PostgreSQL 등)에 개인정보가
      저장/처리되는 것이 "국외이전"에 해당하는가? (서버 위치에 따라
      달라짐 — `harness_09_deployment_runbook.md` 배포 리전 결정 시 함께
      확인 필요)

## 5. 안전성 확보조치
- [ ] 법이 요구하는 안전성 확보조치(접근통제, 암호화, 접속기록 보관
      등)의 구체적 수준을 현재 구현(bcrypt 해시, JWT, branch_id 격리,
      감사로그)이 충족하는가?
- [ ] 개인정보 보호책임자 지정이 법상 의무인 사업 규모/형태에 해당하는가?
